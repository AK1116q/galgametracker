以下保留初始阶段划分；最新实现以上述清单为准，实机和真实用户验证仍待完成。

## M0：本次预备工作

- [x] 完整阅读分享对话，区分明确意图、建议和工作假设。
- [x] 建立产品范围、用户流程、数据模型和内容工作流。
- [x] 建立虚构路线数据、Schema、引用校验与回归测试。
- [x] 配置持续集成及攻略问题模板。

## M1：验证路线内容

- [ ] 选定一部游戏的准确版本；产出版本记录和可使用来源。
- [ ] 人工录入一条完整路线；每个规则都有来源定位。
- [ ] 在对应游戏版本复现并记录证据；无未确认的关键分支。
- [ ] 评估本契约是否表达真实作品所需条件，必要时迭代契约。

## M2：实现领域逻辑

- [ ] 实现三值条件求值与冲突处理；缺历史不推荐，冲突不猜测。
- [ ] 实现合法分支推进及路线前置检查；错选记录真实状态。
- [ ] 实现会话事件重放/撤销；撤销不污染独立通关记录。
- [ ] 增加图可达性、条件冲突、目标可达性验证及真实规则测试。

## M3：最小客户端

- [ ] 确定 Web 或微信小程序；若选 Web 再安装框架，避免双端并行开发。
- [ ] 完成游戏/版本选择、目标选择、当前选择、恢复记录四类界面。
- [ ] 默认隐藏未来剧情及原因；检查 DOM、搜索摘要和辅助文本泄漏。
- [ ] 本地保存与导出/导入；坏备份和 revision 不兼容时不覆盖原进度。
- [ ] 实机测试手机和桌面，完成 product.md 的试用任务。

## M4：小范围验证

- [ ] 在目标大陆网络验证资源加载与核心操作。
- [ ] 由约 5～10 名真实玩家测试；记录失败原因、意外剧透与再次使用情况。
- [ ] 达到一条真实路线完整可用后，再决定扩到 1～3 部作品。

## 后续候选

可视化攻略录入器、私人路线、人工审核投稿、AI 辅助导入、作品请求、云同步、通关卡片、年度报告。当前均未实现，不是 V0.1 承诺。
