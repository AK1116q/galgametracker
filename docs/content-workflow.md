# 攻略数据采集与审核

Web v0.1 已提供私人攻略表单、JSON 修订与导入导出。内置 WA2 首条路线为 `source_checked`（资料交叉核对），仍需实机验证后才能提升为 `verified`。公开资料使用 `public_reference` 并记录事实提炼方式，不能伪装成作者已授权转载。

## 首批数据策略

先选择维护者熟悉、能够确认具体版本、且有可使用来源的一部作品的一条路线。候选包括对话提到的《白色相簿2》，但作品名不代表数据已就绪。优先用本人笔记或作者明确允许整理的攻略。

基础资料与路线知识分开采购/维护。可公开阅读的页面不是自动获得再发布许可；每份来源记录作者、链接或本地材料编号、授权依据及定位。许可不清晰的内容保持草稿。

## 录入步骤

1. 确认作品、发行平台、语言、汉化名称和补丁版本。
2. 记录来源及使用依据；摘取必要的选项和逻辑，避免复制完整剧情。
3. 添加目标路线、前置结局、入口节点和安全标签。
4. 逐节点录入准确选项文本、下一节点和目标相关推荐；写明来源定位。
5. 对需要历史选择的推荐增加条件。不了解的 Flag/好感度不可猜测。
6. 运行 `npm run check`，修复引用、结构和发布门槛错误。
7. 由能复现该版本路线的审核者核对每个节点，记录覆盖路线和证据。
8. 从 `draft` → `in_review` → `verified`；只有 verified 的真实数据才可进入将来的正式目录。

`data/examples` 永远是虚构测试数据，必须保持 draft。程序通过只能说明数据契约符合要求，不能代替人工复现。

## 维护者录入表

| 字段 | 必填内容 |
|---|---|
| 游戏/版本 | 准确版本、平台、语言/汉化 |
| 目标及前置 | 角色/安全名称、必需的已通关路线 |
| 节点定位 | 当前章节/游戏日期/其他不泄露未来的提示 |
| 选项 | 按实际画面顺序录入，稳定 ID 与展示文本分离 |
| 规则 | 推荐选项、适用目标、历史条件 |
| 去向 | 下一关键节点或结局 ID；未知去向不能假定 |
| 来源 | Source ID、页内标题/段落或笔记位置 |
| 审核 | 具体版本的复现方法、覆盖路线、审核人和日期 |

## 纠错与投稿

错误报告包含版本、路线包 revision、节点 ID、实际选项、预期与实际结果，截图/剧透材料默认不展示给其他玩家。确认严重错误后撤回对应 revision 的新导航入口，保留老会话和纠错提示，再发布修正版。

未来投稿默认草稿/私人内容，明确提交后进入审核。AI 导入结果必须逐项人工核对，缺失条件保留为待补充，禁止补写假攻略。社区验证量只是参考，不自动取代证据审核。
