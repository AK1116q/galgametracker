# 数据模型与技术方案

状态：Web v0.1 已实现。React + TypeScript + Vite 提供界面；core 提供共享校验、三值条件求值、记录/撤销、进度重放、备份合并及线性录入适配。复杂作品状态模拟仍在规划中。

## 分层

1. 游戏资料层：名称、别名、外部 ID、版本。未来通过适配器接入元数据源。
2. 内容层：版本限定的路线包，包含路线、结局、关键选择、条件、来源及审核记录。
3. 纯逻辑层：根据目标和确认的历史状态匹配规则，不读取界面、不直接联网。
4. 进度层：按游戏版本和路线包 revision 保存会话、选择事件及已确认结局。
5. 展示层：仅取当前可展示字段，分别适配 Web 或小程序。

工具使用 Node.js 与 JSON Schema，Web 使用 React/Vite，托管使用 Cloudflare Pages。无需云数据库或登录服务。用户已确定 Web 首发、小程序后续；未来小程序复用 core，另写展示和存储适配。

## 核心实体

| 实体 | 关键字段/职责 |
|---|---|
| Game | 稳定 ID、标题、中文别名 |
| Release | 稳定版本 ID、语言、平台/汉化标签；不仅仅是 locale |
| RoutePack | schemaVersion、revision、适用 release、审核状态、来源 |
| Route | 目标、入口节点、前置 Ending ID |
| Choice | 稳定 ID、定位提示、当前文本、选项、带条件的推荐规则 |
| Option | 稳定 ID、版本内准确文本、下一节点/结局引用 |
| Condition | 已选选项相等、Flag 相等、计数器阈值、已完成结局；支持 all/any |
| Ending | 内部 ID、安全标签、隐藏名称、剧透级别 |
| Source | 来源 ID、原作/授权依据、定位方式；示例明确标识 synthetic |
| Review | 审核人、日期、覆盖的路线、复现证据；不是点赞数量 |
| Playthrough | 会话 ID、releaseId、packRevision、routeId、事件日志 |

真实路线通常是带状态的有向图，而非简单树。共通节点可以复用；回档通过撤销事件重放，不依赖倒扣好感度。跨版本逻辑改变时制作独立路线包，不能仅替换翻译文本。

## v0.1 契约的明确限制

样例和 schema 表达多路线、分支、前置结局及条件规则。Flag 和计数器条件仅预留表达能力；自动更新效果、循环、多周目迁移、计时选择及地图调度尚未实现。第一条真实路线若需要这些能力，应先扩展契约及验证案例，不能硬塞线性选项。

`scripts/validate-data.mjs` 检查 schema、重复 ID、悬空引用、规则所引用的选项、来源引用及发布门槛。它不证明攻略真实性，也不执行图可达性/终止性或条件可满足性分析；这些属于后续引擎任务。

## 已实现的推荐引擎契约

输入：固定 revision 的路线包、目标路线、当前节点、玩家确认的选择历史和前置完成情况。

输出：`recommended`（明确的选项集合）、`unknown`（信息不足）、`conflict`（多条冲突规则）、`unsupported`（版本或能力不支持）。

未知 Flag 必须采用三值逻辑，不能当 false；不得把缺失历史当成“没有选择”。同目标的多个满足规则仅在推荐集合一致时合并，否则报 conflict。推荐和分支推进分别处理，玩家实际选择决定历史。结局由玩家确认。

## 持久化与内容升级

采用本地存储，匿名即可使用；已实现备份导出、导入和冲突保护。设备丢失或清除存储会丢进度，界面提供备份入口。导入验证版本、完整引用和事件重放，失败时不覆盖已有数据。

会话绑定不可变 pack revision；数据修订不静默改写旧进度。迁移必须显式验证节点/选项映射，无法映射时保留备份并要求重新定位。已完成结局属于跨会话记录，撤销当前选择不删除历史通关记录。

## 大陆使用体验

核心导航拟从本地/同源读取版本化路线包，避免逐次选择依赖海外 API；字体和基础静态资源本地提供。实际托管、线路和地区可达性需从大陆网络测量后决定，当前不承诺全国稳定访问。API 密钥将来只放服务端。

## Web v0.1 数据扩展

向后兼容地增加 unknown 去向（未覆盖路径，不是结局）、skipTo（显式可跳过的选择）、source_checked（资料核对状态）、public_reference（公开资料事实引用）和审核 method。source_crosscheck 不计入实机 verified 的覆盖证据。

本机工作台支持顺序路线与 JSON 修订/导入，不是公共后台；修订已有攻略必须增加 revision，旧记录继续绑定旧版本。
